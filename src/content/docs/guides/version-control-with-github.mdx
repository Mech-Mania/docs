Version control is extremely important for storing CAD files and software files, and is essential when working on a shared project with other people. The most popular version control system is [Git](https://git-scm.com/), an open-source project, which is often paired using GitHub, developed by Microsoft, as a remote host.

## Installing Git

Firstly, we need to check if we have Git installed on our system.

<Tabs syncKey="OSes">
    <TabItem label="Linux">
        Open the terminal with `Ctrl-Alt-t`, then run 
        ```bash 
        git -v
        
        # output should be something like:
        git version x.xx.x
        ```
        
        If the output is not what is specified above, install Git with one of the following commands then follow the instructions.
        ```bash
        
        # Ubuntu/Debian
        sudo apt-get install git

        # Fedora
        sudo dnf install git
        ```
    
        Now, you should be able to use Git from any terminal session on your computer.
    </TabItem>
    <TabItem label="Windows">
        :::tip
            If using the [Windows Subsystem for Linux](https://learn.microsoft.com/en-us/windows/wsl/) (WSL), switch back to the `Linux` tab.
        :::

        Search in your start menu for `Git Bash`. If it does not show up, then go to the official site for Git, [git-scm.com](https://git-scm.com/install/windows), and download the standalone installer `Git for Windows/x64 Setup`.

        <Image src={img_git_win_installer} width={400} alt="Download for Git Windows installer" />

        Launch the installer by double-clicking on it, then agree to the GNU [General Public License](https://www.gnu.org/licenses/old-licenses/gpl-2.0.html),and use all the default settings on the installer. 
        
        You should be now able to launch Git Bash by searching from the Start Menu on your PC, or from right-click in the file browser, and this is where you will use the Git CLI.

        :::tip
            Windows generally uses backslashes (`\`) to divide files and folders in its paths, but Git Bash uses forward slashes, (`/`), to emulate Linux.
        :::
    </TabItem>
</Tabs>

## Linking Git to GitHub

:::tip
    If you have already used Microsoft's GitHub extension for VSCode before, Git should already be linked, so you may be able to skip this section.
:::

In the settings menu of your GitHub account, go to `Developer Settings->Personal Access Tokens->Tokens(classic)`.

You should see an option to generate a new token.

<Image src={img_PAT_create} width={600} alt="Generate PAT" />

Click on it and select `Generate New Token (classic)`

<Image src={img_PAT_mode_select} width={400} alt="Classic mode token gen" />

You will be prompted for a password, and then will see this screen: 

<Image src={img_PAT_create_permissions} width={600} alt="Set Permissions for PAT" />

:::danger
    DO NOT SHARE YOUR PERSONAL ACCESS TOKEN WITH ANYBODY. This can be used to get access to your GitHub account.
:::

Generally, it is best to select only the scopes, or permissions, that you need and _are going to use_ when generating your Personal Access Token (PAT). However, that is beyond the scope of this guide, so for now select all of the scopes (you can change this later), or read about scopes more [here](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/scopes-for-oauth-apps#available-scopes).

Once you have selected your scopes, scroll down to the bottom and click `Generate Token`. Once it is generated, copy it, because it will only be shown to you once.


To safely load our credentials, we use the [Github Credential Manager](https://github.com/git-ecosystem/git-credential-manager) (or [this link](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git) for Github's guide to the GCM).
<Tabs syncKey="OSes">
    <TabItem label="Linux">
        To install the GCM on linux, we can use the script provided by the [GCM repo](https://github.com/git-ecosystem/git-credential-manager/blob/release/docs/install.md). You will prompted for your password.
        ```bash
        curl -L https://aka.ms/gcm/linux-install-source.sh | sh
        git-credential-manager configure
        ```
        
        The GCM by default doesn't save our credentials to disk, so to store them securely (encrypted), we can set the store to use GPG encryption.
        ```bash
        git config --global credential.credentialStore gpg
        ```

### Remote Origin

All of the commits you have done so far have been on your local copy of the repository. You can fetch the latest Git details (such as latest commit on the remote repo) as such:
```bash
    git fetch origin
```

You can update your local copy with the latest changes by _pulling_ from the repo
```
    # `origin` refers to the remote repo hosted by GitHub
    # `main` refers to the fact that the main branch on your local repo is set up to track the main branch on the remote repo.
    git pull origin/main
```

You can update the remote host with your changes by _pushing_ to the repo.
```bash
    git push origin/main
```

Before pushing or pulling you must always fetch from origin
